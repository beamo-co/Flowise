# Escalate Issue - Support Skill

## Overview

This skill guides the support agent on when and how to escalate issues.

## When to Escalate

### Technical Issues

- Bug in the codebase
- System downtime or outages
- Performance issues
- Data corruption or loss
- Security vulnerabilities

### Complex Requests

- Feature requests requiring development
- Custom integrations
- Enterprise-specific requirements
- Legal or compliance questions

### Customer Indicators

- Repeated contact about same issue
- Customer frustration
- Potential loss of customer
- Press or social media attention

## Escalation Process

### 1. Document Issue

Before escalating, ensure you have:
- Clear description of the issue
- Steps to reproduce
- Customer information
- Any relevant logs or screenshots

### 2. Create Ticket

Use the ticketing system to create an issue with:
- Priority level (P1-P4)
- Category
- Detailed description
- Customer contact info

### 3. Notify Team

- Post in the engineering channel
- Tag appropriate team members
- Provide context

### 4. Customer Communication

- Inform customer of escalation
- Provide ticket/reference number
- Set expectations for response time
- Offer workaround if available

## Priority Levels

| Priority | Description | Response Time |
|----------|-------------|---------------|
| P1 | System down, critical | 1 hour |
| P2 | Major functionality broken | 4 hours |
| P3 | Minor issue, workaround exists | 24 hours |
| P4 | Feature request, enhancement | 1 week |
